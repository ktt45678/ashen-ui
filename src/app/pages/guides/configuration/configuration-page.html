Configuration

Set application-wide component defaults, the motion policy, the validation display policy and every string the library renders, in one call, or one token at a time.

provideAshenUI

Every default in the library is a literal on an input, which means a value you use everywhere has to be repeated everywhere. provideAshenUI() moves those decisions to one place. 

{{ codeProvide }}

Only the keys you pass are configured. Anything you leave out keeps the component's own default, so a partial object is normal: button: { size: 'sm' } changes the size and nothing else.

sn-split-button reads the button token rather than owning one: it renders a button, so an app that says buttons are small means these too.

ToastService is provided in root, so the service-side toast fields (severity, life, sticky, closable) only take effect from a root-level provider. The outlet-side fields (position, animation) resolve through the <sn-toast> element and can be scoped.

Scoping a default

provideAshenUI() is sugar over the individual tokens, and the tokens are the real API. Because they are DI tokens, a default can belong to a component subtree rather than to the whole application. 

{{ codeToken }}

Or to a route, which is where a whole dense section of an app belongs:

{{ codeRoute }}

provideAshenUI() returns EnvironmentProviders, so it belongs in bootstrapApplication or a route's providers. It cannot be used in a component's providers. That is what the raw tokens are for.

A default is only a default

A value written on the element always wins.

{{ codeOverride }}

Falsy values are configurable too. life: 0 means "never auto-dismiss", mask: false means "no backdrop", closable: false means "no close button". None of them fall back to the library default.

Motion

animations takes 'enabled', 'disabled' or 'reduced-motion'. With nothing configured the library already follows the user's prefers-reduced-motion setting, tracked live, so 'reduced-motion' only makes that explicit. 'enabled' overrides an accessibility preference, so use it sparingly.

The setting turns off the CSS transitions and stops overlays from waiting for their exit animation, which is what makes overlay teardown synchronous. Angular's provideNoopAnimations() is honoured for free. 

{{ codeMotion }}

Each component that shows and hides also has an animated input. A component animates only when its own input and the application setting agree.

Enter and exit durations are CSS tokens, for example --sn-dialog-exit-duration or --sn-popover-exit-duration. A closing overlay waits for its running exit animation to finish before it is removed, so a theme can change these tokens without any TypeScript setting.

When a control looks errored

SnErrorStateMatcher decides when a form control is displayed as invalid. The default is Angular Material's policy: invalid and (touched, dirty, or the form was submitted). Two alternatives ship with the library.

Text and translation

Every string the library renders (button labels, placeholders, aria-labels, month names) comes from a text service. There is one per component family, so translating the paginator does not mean touching carousel, tree and colour-picker strings, and an app only ships the services for the components it uses. 

{{ codeIntl }}

Only the groups you name are provided, and inside them only the keys you set change. The group names are common, select, listbox, password, inputTags, chip, dialog, drawer, confirm, message, toast, breadcrumb, paginator, splitButton, panel, splitter, tree, carousel, datePicker and colorPicker, each backed by a service named after it (SnPaginatorIntl, SnDatePickerIntl, …). Each component page lists its own keys.

The date picker's month and weekday names can be derived rather than written out: 

{{ codeIntlLocale }}

Because these are ordinary injectables, a service can also be replaced wholesale, the way to make labels follow a language the user switches at runtime: 

{{ codeIntlInject }}

Migrating. These services replace the single SnIntl class, which carried all 57 keys. SnIntl still exists as a deprecated read-only view over them, and provideSnIntl() still accepts the old flat keys (paginatorFirst rather than paginator: { first }) and routes them to the right service. What no longer works is { provide: SnIntl, useClass: … }. No component reads that class any more.

Icons the library draws for itself

A select's chevron, a dialog's close button, a table's sort arrow: glyphs no app asked for, that components pick on their own behalf. They resolve through SnIconRegistry by semantic name, so remapping one re-skins every component that draws it: one close entry covers Dialog, Drawer, Toast and Message at once. 

{{ codeIcons }}

Keys you leave out keep their default. The defaults are Material Symbols ligature names, matching the font the library ships with.

Changing them after bootstrap

The glyph map is a signal, so an alias set at runtime repaints components that are already on screen. 

{{ codeIconsRuntime }}

provideSnIcons() is app-wide, because SnIconRegistry is a root singleton, so providing overrides in a route or a component is too late to be read. Use alias() for anything that changes later.

This is not how you change your own icons

Three mechanisms exist and they don't overlap. Pick by scope:

You want to…Use
Change one instance's glyph the component's own input, <sn-button icon="save">
Put arbitrary markup there: an SVG, a spinner, a badge IconTemplate (*snIcon)
Re-skin a glyph everywhere the library draws it provideSnIcons() / SnIconRegistry.alias()

Resolution runs in that order: an instance template wins over an instance input, which wins over the registry.
