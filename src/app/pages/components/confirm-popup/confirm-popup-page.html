Confirm Popup

A lightweight confirmation bubble anchored below its trigger. Lighter than ConfirmDialog for quick inline destructive actions - no modal backdrop, contextual placement, and a fixed icon + message + Accept/Reject layout. The severity drives both the icon color and the accept button color.

Accessibility

  • The popup panel carries role="alertdialog" and aria-describedby pointing to the message element, satisfying WAI-ARIA APG alertdialog semantics for confirmations.
  • aria-modal is not set - ConfirmPopup is non-modal; page content behind the popup remains accessible.
  • The trigger element automatically receives aria-haspopup="dialog", aria-expanded (updated on toggle), and aria-controls referencing the panel id.
  • Focus moves to the Reject (least-destructive) button when the popup opens, so accidental keyboard confirmation is minimised. Focus is returned to the trigger element when the popup closes.
  • Escape and outside-click dismiss the popup without emitting reject - these are a neutral dismissal. Only the Reject button emits the reject output.
  • Use a descriptive acceptLabel (e.g. "Delete" instead of "Yes") so screen reader users understand the consequence before confirming.
